# 混凝土桥面板独立网格生成方案

> 最后更新：2026-09-01（v2）

---

## 1. 问题背景

### 1.1 现状

当前混凝土桥面板被当作**单层钢面板**处理，存在以下问题：

| 问题 | 说明 |
|------|------|
| `is_double = False` | `calc_deck_geometry` 中 `is_double = (deck_type == "双层钢面板")`，混凝土走单层分支 |
| 仍然生成横肋 | `make_rib_trans_nodes` 读取 `rib_trans_space` 生成横肋节点，混凝土桥面板不需要横肋 |
| 板单元连接横肋之间 | `make_plate_elems` 在相邻横肋节点间生成 PLATE，网格不规则 |
| `panel_length` 未被使用 | UI 有输入但 MCT 生成代码中未引用 |
| 网格非正方形 | 板单元尺寸 = 横肋间距 × 贝雷梁间距，长宽比可能很大 |

### 1.2 目标

- 混凝土桥面板有**独立分支**，不生成横肋/纵肋
- 以**纵梁上弦杆节点**（桁架梁）或**纵梁节点**（型钢）的 XY 坐标构成已知点阵
- 基于点阵**最优化分割**，使每个分块接近正方形（长宽比 < 2）以模拟双向板
- 默认**分块建模**，采用物理断开方法（与双层面板分节建模一致）

## 2. Z 坐标体系设计

### 2.1 坐标定义

混凝土桥面板采用独立的 Z 坐标体系：

```
桥面板 Z = 0（顶面基准）

纵梁 Z 坐标计算：
  桁架梁上弦杆 Z = 0 - (deck_thickness - truss_chord_height) / 2
  型钢梁 Z = 0 - (deck_thickness - h_steel) / 2

其中：
  deck_thickness = 混凝土板厚 (mm)
  truss_chord_height = 桁架上弦杆高度 (mm)，如 321 贝雷梁 = 100mm
  h_steel = 型钢高度 (mm)
```

### 2.2 坐标关系图

```
        ┌─────────────────────────┐ Z = 0（桥面板顶面）
        │     混凝土桥面板         │
        └─────────────────────────┘ Z = -deck_thickness（桥面板底面）
             ┌───────────┐
             │  上弦杆/型钢 │ Z_beam = -(deck_thickness - h) / 2
             └───────────┘
                   │
             ┌───────────┐
             │  下弦杆/型钢 │ Z_beam - truss_height（保持现有逻辑）
             └───────────┘
                   │
             分配梁 / 桩 等下部构件（保持现有逻辑）
```

### 2.3 与现有逻辑的兼容性

- **桥面板以下所有构件**（分配梁、桩、联结系等）保持现有 Z 坐标计算逻辑不变
- **纵梁 Z 坐标**仅在混凝土分支中重新计算，型钢/桁架梁的其他分支不受影响
- **弹连刚度**：桥面板与纵梁之间采用"连接1"刚度（见第3节）

## 3. 弹连设计

### 3.1 弹连对象

混凝土桥面板需要建立**桥面板节点 ↔ 纵梁节点**之间的弹性连接：

| 桥型 | 弹连对象 |
|------|----------|
| 桁架梁 | 桥面板由上弦杆分割建立的节点 ↔ 上弦杆节点（全部对应节点） |
| 型钢梁 | 桥面板由型钢纵梁分割建立节点 ↔ 型钢纵梁节点（全部对应节点） |

算法分割（接近正方形）的节点不建立弹连。

### 3.2 弹连规则

```
对每个纵梁节点 (x_beam, y_beam, z_beam)：
  找到桥面板中最近的节点 (x_plate, y_plate, 0)
  建立弹性连接，刚度 = "连接1"

匹配规则：
  - X/Y 坐标精确匹配（容差 1mm）
  - 由于桥面板网格基于纵梁节点生成，每个纵梁节点都有对应的桥面板节点
```

### 3.3 弹连刚度

采用用户在 UI 中配置的**"连接1"刚度值**：

```python
stiff_deck_beam = _conn_stiff(conn.get("桥面系横肋与纵梁"))
# 混凝土桥面板复用此刚度值
```

### 3.4 弹连生成函数

```python

    """混凝土桥面板与纵梁之间的弹性连接

    ----------
    plate_nodes_dict : {span_key: [[nid, (x,y,z)], ...]}  桥面板节点
    beam_nodes_dict : {span_key: {beam_name: [[nid, (x,y,z)], ...]}}  纵梁节点
```

## 5. 设计原则

### 5.1 点阵与全局分割

核心约束：**分割线是全局贯穿的**。

```
已知点阵（纵梁节点）：
  X方向：x0, x1, x2, x3, ...（贝雷片节点/弹连点/联起终点）
  Y方向：y0, y1, y2, y3, ...（每排纵梁的 Y 坐标）

形成的初始网格块：
  [x0,x1]×[y0,y1], [x1,x2]×[y0,y1], ...
  [x0,x1]×[y1,y2], [x1,x2]×[y1,y2], ...
```

关键原则：**不能单独分割某一块**。在某 X 或 Y 位置插入分割线，会影响到所有经过该位置的块。即分割是**垂直/水平贯穿**的。

### 5.2 最优化目标

- 每个分块的长宽比尽量接近 1
- 约束：长:宽 < 2
- 分割线只能在已知点阵的 X/Y 坐标之间（或之上）插入

### 5.3 物理断开

默认分块建模，采用与双层面板分节建模相同的物理断开方法：
- 在分割边界处生成**两个节点**（间距 2mm）
- 板单元跳过间隙（宽度 < 4mm 的短板单元不生成）

## 6. 算法设计

### 6.1 输入

```
X_coords: list[float]  — 纵梁节点 X 坐标（去重排序），mm
Y_coords: list[float]  — 纵梁节点 Y 坐标（去重排序），mm
max_ratio: float = 2.0 — 最大长宽比约束
```

**X 坐标来源**：
- 桁架梁：`bailey_shangxiangan_coord_dict` 中所有上弦杆节点的 X 坐标（含接头、竖杆、斜杆、弹连交点），按联分组
- 型钢梁：`steel_node_dict` 中所有纵梁节点的 X 坐标（含联起终点、横肋弹连点、分配梁弹连点），按联分组

**Y 坐标来源**：
- 桁架梁：`bailey_ylst`（每排贝雷的 Y 坐标）
- 型钢梁：`beam_y_lst`（每排型钢的 Y 坐标）

### 6.2 算法：贪心全局分割

由于分割线是全局贯穿的，问题可以分解为**X 方向**和 **Y 方向**独立求解。

#### 6.2.1 一维分割问题

给定一组坐标 `[c0, c1, c2, ..., cn]`，将相邻坐标之间的区间进一步细分，使得所有最终区间的长度尽量均匀，且满足长宽比约束。

**简化模型**：已知 X 方向初始区间 `[xi, xi+1]`，Y 方向初始区间 `[yj, yj+1]`。

对于每个初始区间，计算是否需要插入分割线：
- 区间长度 `L = ci+1 - ci`
- 目标长度 `T`（由长宽比约束和整体均匀性决定）
- 需要的分割数 `k = ceil(L / T) - 1`
- 实际分割间距 `s = L / (k + 1)`

#### 6.2.2 算法步骤

```
输入: X_coords, Y_coords, max_ratio=2.0

1. 计算 X 方向初始区间长度列表: dx[i] = X[i+1] - X[i]
2. 计算 Y 方向初始区间长度列表: dy[j] = Y[j+1] - Y[j]

3. 计算目标尺寸:
   - median_dx = median(dx), median_dy = median(dy)
   - target = max(median_dx, median_dy)  # 以较大者为基准
   - 但不超过 min(dx) 和 min(dy) 的 max_ratio 倍

4. X 方向分割:
   对每个区间 [X[i], X[i+1]]:
     L = dx[i]
     if L > target * max_ratio:
       k = ceil(L / target) - 1
       插入 k 个分割点: X[i] + L/(k+1), X[i] + 2*L/(k+1), ...
     elif L > target:
       k = ceil(L / target) - 1
       if k >= 1:
         插入 k 个分割点

5. Y 方向分割: 同理

6. 合并分割后的 X、Y 坐标列表，生成网格节点 + PLATE 单元
```

#### 6.2.3 算法优化（可选进阶）

上述贪心算法在大多数情况下足够。如果需要更精确的优化，可以：

- **动态规划**：最小化所有分块的最大长宽比之和
- **约束求解**：给定最大长宽比约束，求最少分割数

但对于工程应用，贪心算法已足够，因为：
- 纵梁节点间距本身已较均匀（贝雷片 3m、型钢间距 0.9m 等）
- 主要不均匀来源是联起终点和弹连点的插入，这些位置的分割线是必须的

### 6.3 特殊情况处理

| 情况 | 处理方式 |
|------|----------|
| 区间长度 < min_elem_size | 不分割，直接作为一块 |
| 桥面两端悬挑区域 | 纳入点阵（伸出距离已扩展 span_ranges） |
| 联间隙（制动墩偏移） | 不生成板单元（间隙 < 4mm 跳过） |
| 仅一排纵梁 | Y 方向不分割，板单元退化为线（应报错或提示） |

**可选新增**（未来扩展）：
- `concrete_mesh_size`（网格目标尺寸 m）→ 不设置时自动计算

### 7.2 MCT 生成数据流

```
mcb_generate(trestle_ui_dict, mct_savepath):
  o1 = build_section_material_module(...)     # 截面/材质/板厚
  o2 = build_geometry_module(...)              # 跨径/几何/弹连点

  # === 桥面系分支 ===
  deck_type = _comp.get('deck_type', '单层钢面板')
  if deck_type == "混凝土桥面板":
    o3 = build_concrete_deck_module(...)       # 新函数：混凝土桥面板独立网格
  elif is_double:
    o3 = build_deck_superstructure_module(...) # 双层钢面板（现有逻辑）
  else:
    o3 = build_deck_superstructure_module(...) # 单层钢面板（现有逻辑）

  o4 = build_beam_module(...)                  # 纵梁（桁架/型钢）
  ...
```

### 7.3 关键：纵梁节点的获取时机

当前 `build_beam_module`（步骤4）在 `build_deck_superstructure_module`（步骤3）**之后**执行。
混凝土桥面板需要纵梁节点来生成网格，因此需要调整执行顺序：

**方案A**（推荐）：在 `build_concrete_deck_module` 中**内部调用**纵梁节点生成逻辑
- 优点：不改变现有模块依赖关系
- 缺点：纵梁节点生成逻辑被部分重复

**方案B**：将纵梁节点生成提取为独立子模块，先于桥面系执行
- 优点：逻辑清晰，无重复
- 缺点：需要重构 `build_beam_module`，改动较大

**推荐方案A**：在 `build_concrete_deck_module` 中，根据桥型（桁架/型钢）直接获取纵梁节点坐标，不生成单元（单元由 `build_beam_module` 生成）。


```
PLATE 单元（4节点四边形）：

```

```
GRUP_lst: "桥面板" 结构组（所有桥面板节点 + 单元）
```
